# 模型与技能片段独立层级方案

状态：2026-10-26 用户明确选择“按此方案实现（推荐）”；数据、代码、Inspector 与自动验证已完成，等待用户人工试玩验收。

## 目标与现状

模型与每个技能片段可以独立决定前后顺序。地面法阵、模型后景光效、飞行弹体和命中特效不能共用一个强制层级。

当前 `CombatVisualResources` 给全部单位传入 `TbCombatPresentation.unitRenderQueue`，给所有技能的 Projectile、Impact、Area 片段传入同一 `skillRenderQueue`；校验和 `CombatVisualTests.FormalRunPreloadsAllConfirmedSkillVisuals` 还强制技能队列大于模型队列。这是截图遮挡问题的直接原因。

护体罡环 20043 真实引用三个独立片段：

| 片段 | 正式资源 | 实际内容 | 建议相对模型位置 |
|---|---|---|---|
| 30063 | skill_43_h | 落剑及冲击 | 模型上方，保留短时打击遮挡 |
| 30064 | skill_43_p | 竖直蓝色光柱 | 模型下方，避免持续遮住角色 |
| 30065 | skill_43_s | 地面圆形阵纹 | 模型下方 |

以上内容已查看现有正式 PNG 图集确认；不按 h/p/s 后缀自动推断其他技能的层级，也不生成或修改图片。

## 配置方案

新增一张 `CombatRenderConfig` 源表。每行表达一个模型或一个技能片段的渲染顺序：

| 字段 | 规则 |
|---|---|
| id | 唯一行编号 |
| visualSetId | 可空强引用；模型绑定填写，技能绑定留空 |
| skillId | 可空强引用；技能绑定填写，模型绑定留空 |
| clipId | 技能绑定必填，必须属于该技能真实 Projectile / Impact / Area 引用；模型绑定留空，统一控制该模型待机、移动、攻击 |
| renderQueue | 必填整数，数值越大越后绘制；每条绑定独立填写 |

`visualSetId` 与 `skillId` 必须且只能填写一个。模型绑定按 visualSetId 唯一，技能绑定按 (skillId, clipId) 唯一。同一动画素材由不同技能复用时可有不同层级。

`TbCombatPresentation` 增加 `renderConfigIds` 强引用列表，使正式关卡与性能场景均从当前表现方案获得相同的显式绑定目录。旧的全局 unitRenderQueue / skillRenderQueue 停止用于主体和技能排序，不作为缺配置时的回退值。

初始层级建议如下，数值均写在源表中，不写运行时代码：

| 用途 | 初始 renderQueue |
|---|---:|
| 地面法阵 | 3000 |
| 模型后景光效 | 3002 |
| 角色与怪物模型 | 3005 |
| 普通飞行弹体 | 3010 |
| 前景命中光效 | 3015 |
| 现有血条及伤害数字 | 保持当前 3020 |

这些是初次逐项归类的参考档位，不强制所有 Projectile、Impact 或 Area 必须落在某一档；绑定值可独立调整。对当前实际使用的技能逐片段归类，不按动作类型一刀切。

Unity 透明队列下界 3000、最高可用队列 5000 属于渲染接口技术常量；实际模型、特效和反馈队列值均读取 Luban，不以技术边界充当业务默认值。

## 编辑与运行链路

- 在模型、技能 Prefab 的 Inspector 中提供当前绑定的层级列表；技能多段效果逐行显示片段编号和名称。编辑仅更新层级字段，保留已有位置、缩放、碰撞和资源引用。
- 层级编辑保存回上述源表，再运行 Luban；运行时只消费生成配置。Inspector 中不维护第二套运行时默认值。
- 加载时创建只读绑定索引，缺失、重复、引用不匹配或非法队列均明确报错，不回退统一层级。
- `LoadVisualAsync` 从模型绑定取队列，待机/移动/攻击及白闪保持一致；`LoadSkillAsync` 在每次加载片段时取该技能与片段绑定的队列。
- 保留现有按 `(textureResourceId, renderQueue)` 共享普通材质和白闪材质的缓存键。不同队列不共用可变材质，避免修改一项影响所有技能。
- 使用已有共享资源加载、取消令牌、实体池与退出回收；不新增每帧资源查询、每实例材质或特效 GameObject，不保存预览资产。
- 本轮只定义模型和技能片段的前后层级，不扩展角色之间按 Y 坐标排序、镜头距离、碰撞、技能伤害或新玩法。

## 验收

1. 新表、强引用列表、生成 C# 与 bytes 完整，重新生成与源 Excel 一致。
2. 模型待机/移动/攻击/受击白闪层级一致；每个技能的飞行、命中和各 Area 片段分别符合绑定。
3. 复用同一纹理但绑定不同队列时，材质不串层；同纹理同队列继续共享；缺失和重复绑定被拒绝。
4. 护体罡环的阵纹与蓝色光柱在角色下面，角色轮廓可见；前景落剑或命中火花可在模型上方；不能通过统一下调所有技能来验收。
5. 覆盖既有实际可用技能、两个职业、白闪和退出清理；检查没有改变既有位置、缩放和碰撞。
6. 编译、配置检查、相关自动化和 Unity 实际画面通过后，由用户人工验收。不构建 Win64，不提交或推送。
