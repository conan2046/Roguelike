# 局内构筑与事件补齐实施方案 V1.0

日期：2026-10-24。状态：项目方已回复“按该方案连续实施（推荐）”，确认功能细则、表结构与验收标准，进入 B1。目标保留完整范围：被动与槽位、武器升星和超武、更多技能与怪物、精英与宝箱等局内事件。本文不代表功能已经实现。

# 设计目的

将已有 M1 单局闭环推进为具有明确构筑方向、升星成长、超武质变和地图事件目标的正式可玩版本。所有规则、权重、资源地址、文本、数量、时间、距离及数值进入 Luban；运行时只消费统一配置入口。

本批建议验收规模：6 把基础武器、6 种独立被动、每把武器 5 个星级、6 条超武进化链、12 个有实际结算与表现的技能形态、8 种普通怪、2 种精英怪及既有最终 Boss。事件至少覆盖定时精英、精英死亡掉箱、地图定时宝箱和开箱进化。不以表内未启用资源数量计入完成。

本目标按多批实施，同一目标下逐批校验；只完成基础框架或一条示范链不算全部完成。主菜单、局外养成、Steam、Win64 构建继续维持原排期，不混入本批。

# 名词解释

| 术语 | 定义 |

| 外观武器 | TbHeroWeapon 中的角色叠层外观档位；不承载局内构筑规则 |
| 被动 | 独占被动槽、按等级提供属性或机制修正的对象 |
| 超武 | 满足武器星级与被动条件后，通过开启宝箱获得的替代形态 |

| 精英事件 | 按关卡时间表生成的独立遭遇，不触发最终 Boss 胜利逻辑 |
| 宝箱实例 | 带单局代次与唯一序号的场景掉落，只能领取一次 |

# 已有事实与参考审查

正式入口为 TbStage → CombatRunDefinition → CombatRunModel → CombatRunCoordinator → CombatSession/ECS；CombatUiRuntime 展示状态，CombatVisualResources 和资源服务管理表现。已有升级池支持池条目权重和三种耗尽策略。TbSkill 中大量条目仅为表现目录，不能直接当成可用技能；TbHeroWeapon 为角色外观档位，不能复用为局内武器定义。

|---|---|
| 采用 | 当前纯逻辑模型、固定步进 ECS、Luban 唯一入口、既有资源句柄所有权和序列化 UI 绑定 |

# 功能设定

## 槽位与成长

通用上限沿用框架的武器 6 槽、被动 6 槽，两者独立；角色例外由配置表达，不写死在代码。开局武器占一个武器槽。获得新武器/被动占槽，重复获得只升级已有对象；槽满后过滤未拥有对象，已拥有且未满级的对象仍可出现。武器普通形态 1～5 星，被动首批建议 1～5 级，达到上限后不再进入相应候选。

职业主文档中磐岳有“武器最多 4 槽、单件补偿”的特殊约束；当前 M1 没有正式职业限制。建议本批先完整支持配置覆盖，在正式关卡采用职业主文档的磐岳槽数与补偿，不把所有角色强制写成 6 槽。其他职业机制仍属于后续独立范围。该选择列入本轮确认项。

## 升级与候选

升级池保留现有带权条目及耗尽策略；增加武器获得/升星、被动获得/升级类别。一个构筑对象只占一条候选，避免“新武器”和“武器强化”同时重复出现。过滤结果按稳定 ID 排序后无放回抽取，权重来自池条目与已获得构筑的配置修正，不能用词条名称推断流派。

既有 Attribute/Heal/SkillUnlock 类型保留兼容入口；新正式构筑池不再以无限属性卡替代被动槽位。治疗仍排除满生命状态。升级面板显示对象类别、当前/下一星级、占槽情况及配置描述。候选少于展示数量时继续执行原三种耗尽策略。

## 武器与技能内容

| 武器方向（工作名） | 普通形态的行为 | 超武必须可见的变化 |
|---|---|---|
| 飞刃 | 自动索敌直线弹丸 | 多发/穿透，形成连续扫射 |
| 炎符 | 扇形投递覆盖近中距离 | 扇面扩张并增加命中后的爆发 |
| 落雷 | 目标位置瞬时范围伤害 | 连续落点或连锁覆盖多个目标 |
| 寒阵 | 定点持续伤害区域 | 区域范围与脉冲模式改变 |
| 护体环 | 跟随玩家的近身周期攻击 | 多圈或环绕命中覆盖 |
| 连锁法器 | 邻近目标间有限次数传递 | 更多分支/传递，且同次施法去重 |

以上工作名与配对需要在正式表中替换为明确显示文本。首先核对现有动画、图集、技能 Prefab 与资源清单，复用有完整表现的正式资源。普通/超武共 12 个形态必须具有命中、伤害、冷却、范围和实际画面证据；仅复制资源或改伤害倍率不作为超武质变完成。

只为上述真实技能引入需要的投递与状态能力。现有 Projectile/Melee/TargetArea 首先统一施法请求，再增加扇形、多发、持续区域和有限连锁；不预建召唤、全量 Buff DSL 或未使用的状态表。

## 被动与进化

首批 6 个被动方向：攻击、攻速、范围、生命、移动、生存防御。每个被动有明确等级效果与超武配对，不用六份相同效果换名。作用域区分角色通用与指定武器，等级替换同源修改项，不重复叠加旧等级。

进化条件沿用武器 5 星、对应被动至少 1 级、开启宝箱。条件达成后仅标记“可进化”，不在升级结束时自动进化。每次开箱最多进化一把，多个可进化武器按表中规则确定，未进化者等待下一箱。进化替换原槽，不增加槽数；保留原武器身份和合法冷却进度，旧形态不继续发射。所有条件不成立时走箱子的普通奖励规则。

职业文档还包含“局外金色品质解锁超武”规则，但当前没有局外品质系统。建议本批用关卡构筑配置显式关闭该门槛，保证超武可在真实单局到达；保留将来通过配置接入的边界，不制造虚假局外品质。该选择须确认。

## 怪物与事件

普通怪扩展至 8 种正式启用对象，至少体现慢速密集、快速追击、耐久、飞行等差异；按阶段权重投入。2 种精英分别提供追击压力与范围压力，需要独立属性/技能、可辨识表现和死亡事件。最终 Boss 继续独占胜利判定。

事件按关卡时间线调度：定时精英出现；精英死亡在死亡位置掉落宝箱；地图事件在配置的位置规则下生成宝箱。UI 提示事件到达、精英位置和可进化状态。玩家走到拾取距离开启箱子，暂停战斗展示奖励，领取后恢复原先 Playing/Boss 状态。普通奖励至少支持既有治疗/成长入口，不引入与本批无关的局外经济系统。

先处理单 tick 死亡与掉落，再处理拾取和待展示队列；升级与宝箱同帧到达时有固定顺序，不覆盖面板、不丢奖励。结算优先终止未领取交互，重开清空旧代次事件。表驱动事件跨大步长不能漏发、重复或堆叠为同一时刻全部出生。

# 数值框架与校验路径

保留当前 CombatMath/CombatDamage 的真实两次取整、命中/暴击对抗与冷却下限，不以理论参考替换已经运行的公式。既有职业数值文档用于目标约束，Tools/Numerics 旧占位常量不直接写入正式配置。技能/武器与怪物的具体数值在独立 Excel 中维护。

| 校验 | 计算/验证方法 |
|---|---|
| 单次伤害 | floor(floor(A²/(A+D×K)×随机倍率)×暴击倍率)，使用实际表内参数与随机上下界 |
| EDPS | 按固定 tick、实际命中/暴击、投递数量、穿透去重、区域脉冲及冷却运行得到；理论单体期望仅作旁证 |
| 生存 | 目标同一攻击条件下模拟受击死亡时间；护甲/闪避/无敌分别记录，避免把不同机制重复折算 |
| 星级收益 | 同一武器逐星验证单体与群体输出、范围、峰值实例数及实际结算变化 |
| 超武收益 | 同场景比较普通满星和超武；除数值外检查行为形态改变，不能以截图光效替代命中证据 |
| 到达性 | 按真实经验曲线/升级池，固定种子多局验证武器满星、被动前置与宝箱时间窗能相遇 |
| 池合法性 | 满槽/满级/满血、仅剩一个候选、全部耗尽、多个进化候选均有明确结果 |
| 资源/容量 | 对最坏构筑计算弹丸、区域、连锁请求和特效容量，验证扩容、清场及资源释放 |

理论参考来自数值技能内置 EHP/EDPS、属性收益与概率期望框架；与本项目已有公式不一致的通用参考不作为重写依据。本方案不引用用户历史商业化数据，也不把占位数值包装为已实测平衡结论。

# UI、资源所有权与异常流程

UI 用正式 Prefab 序列化槽位、星级和事件/宝箱奖励控件；布局不在运行时硬调。现有 HUD/升级面板按明确字段扩展，不覆盖场景或既有手调 Transform。新增正式 UI 资源通过 TbResource 指定 GameAsset 包，ANI/Raw 资源继续按已有规则归属。所有资源键与文本来自表。

定义聚合时计算全部星级、进化、精英和事件资源的预加载闭包；不能只预加载初始技能。Runner 拥有初始化取消令牌、World、资源句柄和 UI 实例；加载部分失败、退出、重开均释放到明确所有者。模型不接触 Unity 对象。弹丸/区域/宝箱使用运行时池或明确销毁路径，不能序列化临时对象。代次校验拒绝旧面板回调、旧怪死亡、旧事件领取。

配置缺失、非法权重、环状进化或不可解析资源在入局前报明确表名/ID/字段；不落回 C# 默认值。运行时部分加载失败需撤销已创建对象并回到可诊断状态，不留下半个战斗 World。

## B2 技术细化（已确认范围内）

- 范围统一沿用 TargetArea 投递；TbSkillCombat 显式配置持续毫秒、脉冲毫秒及是否跟随拥有者，不新增重复投递类型。脉冲总数从整数毫秒推导，避免寿命边界多打一次。
- Projectile 配置 Targeted/Fan/Radial、弹数、总扇角、额外穿透或连锁次数、连锁范围。穿透与连锁互斥；命中按目标生命周期去重，命中预算必须适配原生内联容器。
- 连锁超武本批采用延长单链和扩大跳转范围；一次施法由一条链承担，命中记录覆盖整条链，避免并行弹丸重复命中同一生命周期。未增加未共享去重记录的分支链。
- 六个结果技能进入正式关卡预加载闭包。进化条件只产生宝箱候选；满星和被动本身不会自动进化。领取后同槽替换、保留冷却比例，已经出生的弹丸和区域继续持有旧快照。
- 持续区域由会话拥有原生列表；暂停冻结、拥有者死亡或换代终止、重开清空、退出释放。随身 ANI 使用同一拥有者生命周期跟随位置。
- 本批激活现有技能资源的碰撞/表现编辑节点，保留既有正式技能的手调布局；禁止调用生成预览资源的旧批量生成方法。Tower 参考路径在本机不可访问，已记录，按当前分层和生命周期约束实现。

每批均先完成其正式表数据与 Luban 生成，再写消费者与测试；通过上一批门禁后继续。性能专项另行安排受控窗口，不与编辑器回归并发。本目标不以构建 Win64 作为每轮验收下一步。
