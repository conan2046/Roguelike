现有TbPerformanceScenario5的目标为平均FPS≥60、整帧P95≤16.67ms、测试热路径单帧GC≤1024字节，并要求模拟欠账不持续增长。六组均实际执行Burst，最小存活数与开始/结束视野内数量等于目标数；出生重叠、越界均为0。

测试热路径测得单帧GC分配均为0；Editor全局仍有分配，原始CSV分开保存两者，不能据此宣称整个游戏零GC。各档World更新P95约1.6～2.3ms，明显低于模拟耗时。模拟欠账为31～60秒量级，说明当前负载不能维持真实60Hz吞吐。

## CPU阶段定位

另用500只、初始武器进行10秒预热+10秒短时诊断，临时启用CPU Profiler并恢复设置。此诊断只用于定位，不替代上表完整样本。

| 原生阶段 | 每渲染帧累计P95 ms |
|---|---:|
| 移动/建索引 | 124.4922 |
| 攻击收集 | 0.4520 |
| 弹丸扫掠 | 0.0978 |
| 持续区域 | 0.0029 |
| 伤害排序/结算 | 0.0121 |
| 回收/Transform | 0.3722 |

该次整体模拟P95为125.6777ms。按同组CSV累计时间计算，移动/建索引占六个已标记阶段的 **99.28%**；百分位来自不同帧，不能直接把各行P95相加。当前首要方向是`CombatTickJob.MoveAndIndex/MoveCylinder`，不是继续削减武器内容。

已知实现风险：每单位移动会重建其网格归属；每次接触扫描邻格并重复通过ComponentLookup读取候选，接触次数上限随单位总数增长。尚需计数或对照实验区分状态读取与重复接触各自的成本；本轮没有改碰撞算法或伪称已经修好。

基础负载DrawCall约为3×怪物数+13；六超武负载另增加表现批次。后续还需核对透明排序/血条的批次，不能仅凭该计数断言是某个Shader开关。已有URP Forward+兼容提示本轮未修改。

## 测量边界

- 这是独立测试场地的Editor容量诊断；为容纳合法阵列，场地在内存中扩展，正式地图及碰撞体原值不变。六超武使用正式通用六槽配置，是上界夹具，不是磐岳自然可持有六武器的证据。
- 保持补怪和玩家恢复以维持负载；单局经验、掉落、升级、宝箱及HUD调度未包含。实际关卡的密集聚怪与正常镜头，还需优化后单独复验。
- Editor/TestRunner/MCP环境、扩大后的镜头和本机负载都限制了数值外推；没有Player/GPU独立时序数据，不把结果当作Steam发布包指标。本轮不构建Win64。
- 早期探索组的旧间距重叠、默认180秒超时、越界单位被强制扫回边界已分别定位；这些原始记录保留但排除正式容量结论。专项现为显式900秒超时，逐帧让出主线程。
- 本轮新增可单独启动的Explicit探针和六个技术Profiler阶段标记，未修改业务配置、结算顺序、Actor碰撞体、Scene或Prefab。
