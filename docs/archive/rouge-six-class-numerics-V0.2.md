# rouge 六系职业数值统筹与战斗公式方案 V0.2

> 上游：`rouge-six-class-design-V0.1.md`（机制/卡池/原型）、`rouge-feature-backlog-and-priority.md`。
> 公式来源：`Assets/Scripts/Features/Combat/CombatMath.cs`、`CombatDamage.cs`（实测读取，非推测）。
> 基准来源：`TbCombatRules`(ID1)、`TbAttributeProfile`(ID1 玩家调试)、`TbMonster`/`TbBossEncounter`。
> 计算模型：`.local/numerics/balance_model.py`（可复现，后续迁入 `Tools/Numerics/`）。

## 1. 结论先行

1. **现有战斗公式可用但有三处结构性风险**：① 玩家基准 `Defense=0 / Critical=0 / Evasion=0`，**任何百分比偏移对这三项无效**（V0.1 的「防御 130%」「暴击 +20%」是无效设计，必须改为绝对增量）；② 减伤模型 `DR = DEF·k / (敌人攻击 + DEF·k)` **随敌人攻击力衰减**，高防系在普通怪前近乎无敌、在 Boss 前平庸，体验割裂；③ 普通怪 `Defense=0` 使伤害退化成纯线性 `ATK`，攻击系无边际衰减。
2. **六系平衡用「场景加权战力」模型求解**：`W = EDPS^0.6 × EHP^0.4`，按普通怪 60% / 精英 25% / Boss 15% 加权。已迭代四轮，**六系偏差收敛在 +1.1% ~ +2.3%（彼此差 ≤1.2%）**。
3. **差异化方向应对标竞品做「强修正 + 明代价」**，而非均衡微调。基准幅度建议：核心属性 ±15~30%，代价属性 −20~−40%（竞品 Vampire Survivors 实际用到 −90% ~ +250%）。

## 2. 竞品参考与启示

| 竞品 | 角色差异化做法 | 关键数据 | 对本项目启示 |
|---|---|---|---|
| Vampire Survivors | 起始武器 + 19 项玩家属性修正 + 随等级成长 + 明代价 | Might 修正区间 −90%(Rose) ~ +250%(Megalo)；Ghost 免疫伤害但 −100% Might；Exdash 全属性削弱换 +100% Luck | **修正幅度要敢做大，代价要写进角色卡**；代价本身就是角色记忆点 |
| Vampire Survivors | 属性分 19 项：MaxHealth/Recovery/Armor/MoveSpeed/Might/Area/Speed/Duration/Amount/Cooldown/Luck/Growth/Greed/Curse/Magnet/Revival/Reroll/Skip/Banish | 部分属性（Growth/Greed/Luck/Magnet）不进战斗公式，只改资源与随机 | **非战斗属性是低风险差异化空间**，优先用（拾取/经验/金币/重roll） |
| 20 Minutes Till Dawn | 每角色一个专属能力 + 击杀精英掉落该角色专属升级 | 8 角色，专属能力决定流派；专属升级由精英掉落驱动 | **角色专属成长应绑定局内事件**（精英/宝箱），与本项目 §2.8 地图节奏天然契合 |
| Brotato | 6 武器槽 + 角色以「属性修正 + 硬性限制」定义 | 限制型角色（如只能带 1 武器、禁用某类） | **限制比加成更能制造差异**，本项目可用「卡池禁用/槽位上限」做代价 |
| Soulstone Survivors | 主动技能 + 冷却 + 大量技能组合 | 技能密度显著高于 VS | 属深度方向，M3 后再评估，不进 M2 |

**三条可执行结论**：
- 差异化 = **起始武器（1）+ 属性修正（2~3 项，幅度大）+ 硬性代价（1 项明确）**。
- 优先使用**非战斗属性**（拾取半径、经验、金币、重roll 次数）做差异化——不进伤害公式，不会破坏平衡模型。
- **代价必须显性**：写进选角界面第二行，玩家看到「−30% 攻击」比看到「+40% 生命」更容易记住角色。

## 3. 战斗公式诊断（基于实测代码）

### 3.1 现有公式

| 环节 | 公式 | 来源 |
|---|---|---|
| 伤害 | `D = floor( ATK² / (ATK + DEF·k) × rand/10000 ) × (暴击 ? 1.5 : 1)` | `CombatMath.Damage` |
| 命中率 | `Hit·Hp / (Hit·Hp + Ev·Ep)`，分母为 0 时用 `ZeroHitBp` | `CombatMath.ProbabilityThreshold` |
| 暴击率 | `Crit·Cp / (Crit·Cp + CritRes·Cp')`，分母为 0 时为 0 | 同上 |
| 攻击间隔 | `max(baseInterval / AttackSpeedMultiplier, 0.05)` | `CombatMath.AttackInterval` |
| 减伤（推导） | `DR% = DEF·k / (敌人攻击 + DEF·k)` | 由伤害公式反推 |
| 规则常量 | 随机 8000~12000bp（期望 1.0）、暴击 1.5×、最短间隔 0.05s、玩家受击无敌 0.5s、模拟 60Hz | `TbCombatRules` ID1 |

### 3.2 风险与修正建议

| 级别 | 风险 | 后果 | 修正方案 |
|---|---|---|---|
| 🔴 P0 | 基准属性为 0（Defense/Critical/Evasion），百分比偏移无效 | V0.1 的三项系别偏移全是空值 | **改为绝对增量**，在 `TbAttributeProfile` 直接给每系一份完整方案 |
| 🔴 P0 | 减伤随敌人攻击力衰减；普通怪 ATK=8，DEF=4 即减伤 33%，DEF=8 即 50% | 高防系割草无双、Boss 战平庸 | ① 用角色侧 `DefenseParameter` 调节（已有字段，当前全员 1.0）；② 或给敌人加 `AttackParameter` 分档 |
| 🟡 P1 | 普通怪 `Defense=0`，伤害退化为线性 ATK | 攻击系无边际衰减，后期单向膨胀 | M2 扩展怪物时给中后期怪配置递增 Defense（建议 0→3→6→10 分档） |
| 🟡 P1 | 玩家 `Critical=0` 且怪 `CritRes=100`，暴击需 Crit≈33 才有 25% 率 | 暴击系投入产出需重新标定 | 已按 `Crit/(Crit+100)` 建模，六系基线中 H_0=15（13% 率）、Z_0=12（10.7% 率） |
| 🟢 P2 | 攻速下限 0.05s，J_0 攻速流有硬性天花板 | 攻速叠加到 10×即触顶，性能也承压 | 建议攻速系上限设 2.0（间隔 0.25s），并在性能验证后回写 |

## 5. 平衡框架

### 5.1 战力函数

```
EDPS = D(ATK, 目标DEF) / 攻击间隔 × (1 + 0.5 × 暴击率) × 独立乘区
EHP  = HP / (1 − DR%) / (1 − 闪避率)
W    = EDPS^0.6 × EHP^0.4
W加权 = 0.60×W(普通怪) + 0.25×W(精英) + 0.15×W(Boss)
```

α=0.6 的取值依据：Survivor-like 中「清怪速度」决定生存压力，输出权重高于生存；该系数本身应随实测数据回归修正。

## 10. 诚实边界

- 平衡模型中的 **α=0.6 输出权重、场景权重 60/25/15 为经验取值**，未经实测回归；正式值应在 M2 试玩数据回来后修正。
- EDPS 计算统一以 **Projectile 基础间隔 0.5s** 为口径（便于横比），六系实际起始武器不同，武器切换后需重算。
- 独立乘区（仆从/领域）当前按**理想覆盖率 100%** 估算，实战中领域覆盖率与仆从存活率均低于此值 → **K_0、Y_0 实际强度低于模型值**，需在 M2 实测后上调乘区补偿。
- 竞品数据来自公开 Wiki/媒体（VS Wiki、TheGamer、PCGameSpotlight），**未经一手实测核对**，仅作设计幅度参考。
- 移速未进战力模型，其真实收益（走位躲避）需在真机验证后折算，当前视为免费额度可能存在低估。
- 六系中文名未定，本文档沿用 B_0/H_0/J_0/K_0/Y_0/Z_0 资源前缀。
