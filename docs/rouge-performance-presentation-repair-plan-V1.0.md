# 表现桥与绘制性能修复方案 V1.0

2026-10-25。状态：用户已确认，2026-10-25在新任务接续实施R0—R4。接续已批准的CPU修复；本批属于新的表现/渲染改造范围。

## 问题与边界

CPU修复后，500/1000怪四组已达到现有TbPerformanceScenario预算；2000怪基础/六超武平均47.38/41.35FPS、帧P95 27.65/30.84ms。六组都保持60Hz、热路径GC0、欠账稳定。完整证据见`rouge-performance-cpu-repair-report-20261025.md`。

2000基础组表现桥P95约6.26ms，World约1.46ms，DrawCall中位6013。模拟P95约14.53ms包含同帧多个固定Tick，不能直接把各P95相加。上述证据表明仍需削减主线程表现与绘制成本，尚不能确定GPU瓶颈或单一Shader根因。

保留正式数值、怪物数、出生/视野、碰撞、移动、技能、ANI帧和锚点、血条尺寸/颜色、透明外观、命中半透明白闪及现有UI。不得减少负载、隐藏血条、缩碰撞体、降低画面比例或通过相机裁掉单位达标；不覆盖Scene/Prefab、不保存预览资产、不构建Win64、不提交/推送。

## 当前入口与职责

`CombatRuntimeRunner.AdvanceFrame`→`CombatSession`固定Tick→`CombatEntityVisuals.Synchronize`/`CombatFeedbackVisuals.Synchronize`→`LateUpdate`中的自有World更新→Entities Graphics。

- 会话持有纯战斗状态和原生容器；资源服务负责正式ANI/纹理加载。
- `CombatEntityVisuals`按单位采样ANI、写MaterialMeshInfo和RenderBounds；当前每个可见单位每帧均写入，即使帧/材质未变。
- `CombatFeedbackVisuals`持有血条/飘字等运行时实体与共享资源，当前与单位主体分开绘制。
- `CombatVisualResources`及反馈材质已设置`enableInstancing=true`并共享资源；不能把再次打开此开关当成修复。
- 透明队列、材质与逐帧Mesh、DOTS/URP兼容路径需要按实际绘制证据核对；不直接切换渲染路径或改成裁切透明。

## 实施顺序

| 批次 | 工作 | 门禁与证据 |
|---|---|---|
| R0 定位 | 仅加技术Marker，细分单位状态读取、ANI采样、渲染组件写入、血条、飘字、技能反馈与World；核对Frame Debugger/Profiler可用能力 | 捕获2000两负载、实际绘制路径与批次原因；单项诊断开关只存在测试，不改正式规则 |
| R1 表现桥 | 优先评估每渲染帧一次会话只读快照→主体/血条/反馈共享读取；只在Mesh/材质/Bounds或血条状态改变时写对应组件 | 外部属性修改、同帧出生、死亡复用、升级、白闪、暂停/重开均读取新状态；不能直接用可能过期的Tick缓冲替代ECS |
| R2 绘制批次 | 依据R0确认的原因，评估保持透明结果的分组/实例数据和血条绘制；优先保持原资源与材质接口 | 先有内存原型与同画面比较，再落地。若必须改变透明排序、Shader接口或URP路径，补充具体取舍并确认，不在本方案中预设切换 |
| R3 回归 | 普通Edit/Play、真实ANI/白闪/血条及技能重叠画面、暂停/结算/重开/退出 | 无穿插层级、透明边缘、锚点、血量显示、资源取消/释放回归；配置/Scene/Prefab哈希保持 |
| R4 容量 | 重跑同一合法场地500/1000/2000×基础/六超武，每组10秒预热+60秒采样 | 六组原目标：平均FPS≥60、帧P95≤16.67ms、热路径GC≤1024B、欠账稳定；全部真实Burst、人数/可见数保持 |

R0—R1可先闭环；R2只实施证据支持且保持既有外观的部分。不能用缩短采样、叠加各阶段P95、关闭绘制或Editor短样本替代完整验收。仍失败则保留失败结果及下一处可行动定位，不宣称M1.5完成。

## 数据与技术常量

本批预计不改玩法配置。技术Marker、脏标记、快照容量/代次属于实现边界；容量从实际槽数和现有资源表推导，不增加业务兜底值。如确需新增表现参数，先补TbCombatPresentation等对应Luban表结构/数据并生成，再由代码读取；不写进Prefab/Scene或另一套默认配置。

快照仅在任务完成后刷新/借用；借用范围限制为当前同步帧，结构扩容不能使消费者继续持有旧指针。动态出生与属性/技能同步完成后必须可见，重开清空代次，退出与异步取消释放全部原生容器、运行时Mesh/Material/Texture及句柄；不序列化临时对象。

## 参考与取舍

AGENTS指定的Tower Battle参考路径本机仍不可访问。本方案依据当前DOTS、资源服务和会话所有权边界，采用集中采样、职责分离、资源共享、变更时写入与显式清场。拒绝HotFix/网络/全局单例、旧表链、业务硬编码及资源预览副本。现有材质实例化开关已开启，拒绝未经测量的“改一个开关即可达标”。

本方案已获用户确认；既定范围内直接实施，透明排序、Shader接口或URP路径变更仍需补充取舍并单独确认。Unity与测试仍沿已有授权自主通过当前项目MCP完成；无需逐操作确认。人工画面/可玩性验收及以后明确要求的Player/Win64另行安排。
