# Roguelike 属性与战斗底座实施方案

日期：2026-09-05。核对基线：main / fec6322。修订依据：《战斗公式及属性调整V1.0》正文与伤害流程图；用户指定暂不需要元素属性。

本阶段交付属性计算、伤害结算和最小战斗闭环，为后续武器升星、被动、经验升级提供统一入口。属性与公式按用户提供文档修订，替换此前固定防御常数的减伤模型，并纳入命中、闪避、暴击与抗暴。元素属性及相关加成、抗性、减免、克制均不进入本阶段。用户已确认进入数据配置阶段，具体落表记录见第 11 节；战斗运行器尚未实现。此前千实体测试只覆盖单帧贴图渲染与移动，不构成完整战斗验收。

## 2 本阶段功能边界

首版采用 ECS 模拟，MonoBehaviour 只负责输入、启动、相机及调试 UI。先在开放的测试场地验证：一个玩家移动、一个近战怪类型追击、玩家自动发射直线弹丸、双方扣血、死亡、回收与重新开始。

玩家可以边移动边攻击。玩家死亡后停止战斗计时和新增攻击，展示可读结果并可重新开始。胜利条件暂不定义。经验球、掉落收益、升级三选一、Boss、武器升星、局外成长和正式关卡节奏在闭环稳定后推进，不能把本阶段完成记为完整 M1 完成。

首版测试场地为独立入口与资源，不改动已有 MCPDemo 的用户编辑内容。测试场地位置、边界、实体数量、种子及资源 ID 均来自测试表。接入现有复杂地图阻挡与绕障寻路作为独立后续工作，首版只保证场地边界约束，不宣称已完成地图寻路。

## 3 属性定义与修改规则

单位保存基础属性和对抗参数，技能保存基础间隔和范围，避免两处配置互相覆盖。原文新增的九个属性全部保留，伙伴表在本项目对应 TbCharacter，怪物表对应 TbMonster；双方通过属性方案引用这些值。

| 拟定属性 ID | 语义 | 单位 | 首版要求 |
|---|---|---|---|
| 1 | MaxHealth 最大生命 | 点，整数 | 大于零；当前生命独立保存在运行时 |
| 2 | Attack 攻击 | 点，整数 | 非负 |
| 3 | Defense 防御 | 点，整数 | 非负；通过目标防御参数参与伤害公式 |
| 4 | MoveSpeed 移速 | 世界单位每秒 | 非负；不直接复用像素速度 220 |
| 5 | AttackSpeedMultiplier 攻速倍率 | 无量纲 | 大于零；基础值建议 1 |
| 6 | DefenseParameter 防御参数 | 无量纲 | 大于零，目标属性 |
| 7 | Hit 命中值 | 点 | 非负，攻击者属性 |
| 8 | Evasion 闪避值 | 点 | 非负，目标属性 |
| 9 | HitParameter 命中参数 | 无量纲 | 大于零，攻击者属性 |
| 10 | EvasionParameter 闪避参数 | 无量纲 | 大于零，目标属性 |
| 11 | Critical 暴击值 | 点 | 非负，攻击者属性 |
| 12 | CriticalResistance 抗暴值 | 点 | 非负，目标属性 |
| 13 | CriticalParameter 暴击参数 | 无量纲 | 大于零，攻击者属性 |
| 14 | CriticalResistanceParameter 抗暴参数 | 无量纲 | 大于零，目标属性 |

非攻击属性的基础修改接口建议为：属性最终值 = Clamp((基础值 + 固定加值之和) × (1 + 百分比加值之和), 表内下限, 表内上限)。这属于本项目接口建议，不替代参考文档中特定来源的攻击聚合公式。同类百分比相加，首版不开放任意独立连乘区。百分比使用整型万分比存表，10000 表示 100%；数学单位换算属于技术常量，实际上下限与调整量属于表内配置。

伤害公式的攻击输入 A 是本次攻击的最终有效攻击。原文有“城主攻击力＋英雄攻击力”与后文“装备攻击力＋宝石攻击加成＋英雄技能”两种展开描述，不能将两段直接叠加，否则可能重复计入来源。本阶段没有城主、伙伴养成和宝石系统，先使用 Luban 明确配置并经属性修改后的有效攻击 A；保留来源聚合接口。原文英雄升级的 0.08、宝石重复技能系数等属于旧养成规则，不自动带入当前战斗底座。

本阶段技能负责投递方式、间隔、范围与表现，不在最终 A 之外再次乘一次技能伤害系数或加固定伤害。后续增加武器升星、技能系数或来源聚合时，先定义 A 的来源规则，再在这一入口统一计算，避免套入原文公式两遍。

生命、攻击、防御在最终属性处向下取整；移动速度与攻速保留小数。所有输入必须有限，溢出、缺失必需属性、重复语义和非法范围在进入战斗前报出表名、字段和 ID，不采用代码默认值继续运行。

修改项以来源实例标识管理，替换同来源而非重复叠加；移除后从基础值重算，禁止通过浮点反向减法恢复。首版实现固定加值与百分比加值接口及测试，不提前实现 Buff 时间系统。

最大生命改变时，保持当前生命数值，再将其截断到新上限；增加最大生命不自动回血。回血必须经独立生命变更入口，且不能复活已死亡单位。当前生命只能由初始化、生命变更或伤害结算模块写入。

有效攻击间隔 = Max(技能基础间隔 / 单位攻速倍率, 战斗规则最短间隔)。间隔变更保留冷却完成比例，避免修改攻速额外触发攻击。单技能冷却独立，首版双方各只有一个默认技能。

## 4 伤害与死亡规则

采用参考文档的攻击平方公式，去掉目标元素减免系数。防御参数属于被攻击目标的基础属性，不能用全局防御常数替代。

```text
A = 本次攻击的最终有效攻击
D = 目标防御
K = 目标防御参数
R = 本次伤害随机倍率，原文范围 [0.8, 1.2]
基础伤害 = Int(A² / (A + D × K) × R)
命中率 = (攻击者命中值 × 攻击者命中参数)
         / (攻击者命中值 × 攻击者命中参数 + 目标闪避值 × 目标闪避参数)
暴击率 = (攻击者暴击值 × 攻击者暴击参数)
         / (攻击者暴击值 × 攻击者暴击参数 + 目标抗暴值 × 目标抗暴参数)
概率阈值 = Floor(概率 × 10000)
判定成功 = 独立随机整数 [1, 10000] <= 概率阈值
结算伤害 = 未命中或伤害被阻止 ? 0 : Int(基础伤害 × 暴击倍率)
实际生命损失 = Min(当前生命, 结算伤害)
```

普通命中倍率为 1；暴击倍率按原文流程图为 150%，作为战斗规则入表。原文基础伤害公式包含 int，流程图随后乘 150%，本版明确采用“基础伤害先取整，暴击后再取整”；最终生命按整数变化。非负输入下 Int 与向下取整一致。本版不添加此前建议的最小伤害保底，高防御下允许命中但伤害为零。

边界补充属于本项目规则建议，原文未定义：A=0 时直接为零，避免 0/0；命中双方有效值均为零时按必中处理；暴击双方有效值均为零时按不暴击处理。系数必须正数、数值必须非负且有限，非法配置在入局前报错。计算使用足够宽的中间类型并检查结果范围，不能先在整型中计算 A² 导致溢出。

伤害随机建议实现为独立整数 [8000,12000] 除以 10000，端点包含；这是对原文区间的离散实现建议。上下限入表，与命中、暴击的 [1,10000] 概率抽样区分。原文未定义浮点随机精度，不将此精度说成原文既有规则。

顺序固定为：目标存活及阵营检查 → 几何接触/弹丸碰撞 → 检查无敌与免伤次数 → 命中随机 → 暴击随机 → 伤害浮动与基础伤害 → 暴击倍率 → 生命变化 → 死亡标记 → 失活与表现回收。几何碰撞只是候选目标，还必须执行命中率判定。群攻按每个目标独立进行命中、暴击和浮动抽样，不能整个技能共用一次结果。伤害请求不能直接广播到全局托管事件总线。

无敌时直接零伤害，不消耗免伤次数；非无敌且免伤次数大于零时扣一次次数并阻止本次伤害，不再抽命中或暴击。该优先级和次数消耗方式是对原文未细化处的补充。本阶段实现免伤次数的结算入口和测试，不扩展通用 Buff 系统、护盾或免伤次数奖励玩法。界面与统计区分无敌、次数免伤、闪避、普通命中、暴击和命中零伤害。

同一模拟 tick 的伤害请求按目标生成序号、攻击者生成序号、攻击序号稳定排序。生命首次归零时生成唯一死亡记录，后续请求不重复触发死亡，也不计算额外有效伤害。复用实体须更新生命周期序号，旧弹丸或延迟事件不能误伤复用后的对象。

弹丸生成时快照攻击者的有效攻击、命中值/参数、暴击值/参数；接触时读取目标防御/参数、闪避值/参数和抗暴值/参数。攻击者死亡不撤销已飞出的弹丸。按同 tick 开始时的存活状态产生攻击请求，允许双方在同一 tick 相互击杀。结算为零的伤害也可记录命中，但不计生命损失。随机流按战斗种子、攻击序号、目标生命周期序号和抽样用途派生，不使用并行 Job 共享可变 RNG；减少目标数量不能改变其他攻击的随机结果。

## 5 攻击与移动规则

玩家自动选择范围内最近存活敌人，等距时按生成序号选择。无目标不消耗冷却；开始战斗时冷却就绪。直线弹丸朝发射时的目标位置飞行，不追踪，首次几何接触有效敌人后生成一次结算请求并失活，即使目标闪避或免伤也不继续穿透；用上一位置到当前位置的扫掠判定，避免高速穿透。寿命到期且尚未接触时回收。

怪物以玩家位置为目标直线追击，进入攻击范围后停步，按自身默认技能间隔进行近战攻击；离开范围则继续追击。怪物之间允许重叠，首版没有推挤、分离力与绕障。攻击距离按圆形碰撞体边缘计算，避免贴图尺寸影响判定。

玩家受到正数实际生命损失后有可配置的短暂无敌时间，避免重叠怪物在一帧内使其归零。同 tick 多次接触伤害按稳定顺序接受首个有效伤害，后续按无敌状态拒绝；闪避、免伤和结算零伤害不触发新的受击无敌。这个规则仅用于玩家，怪物不自动获得受击无敌。

模拟采用固定 tick，输入每帧采集并交给模拟，暂停时冻结冷却、弹丸寿命与无敌时间。帧内补算次数上限来自战斗规则表；超限积压保留并记入性能报告，不能丢弃模拟工作后仍判定性能通过。渲染可插值，固定种子加相同输入时间线可复现同机结果；不承诺跨 CPU 平台逐位确定性。

## 6 Luban 表结构建议

保持现有工作簿命名规范、有效区居中、ID 不重排，新增引用均由 Luban #ref 校验。字段建议以下表为准，最终值在下一步落表时逐项核对。

| 表 | 拟定变更 | 使用边界 |
|---|---|---|
| TbAttribute | 增加 EAttributeType 语义、数值类型、单位、下限、上限；添加 ID 1–14 | 含原文九个新增属性；枚举为封闭程序语义，不能用显示名或 ID 魔法数分支 |
| TbAttributeProfile 新增 | id、name、values 列表；列表元素为 attributeId 和 value | 基础属性唯一来源；一个 profile 不允许重复属性 |
| TbCharacter / TbMonster | 新增可空 attributeProfileId、defaultSkillId；bodyRadius | 未配置战斗字段的既有资源条目只可预览，禁止参与战斗 |
| TbSkill | 新增可空 combatProfileId | 既有视觉目录不批量填充虚构技能数值 |
| TbSkillCombat 新增 | id、deliveryType、baseInterval、range、projectileSpeed、projectileLifetime、projectileRadius | 首版不额外乘技能伤害系数；弹丸字段对近战可空，按类型校验 |
| TbCombatRules 新增 | id、damageRandomMinBp、damageRandomMaxBp、criticalMultiplierBp、zeroHitDenominatorRateBp、zeroCritDenominatorRateBp、minAttackInterval、playerInvulnerabilitySeconds、simulationHz、maxCatchUpSteps、targetRefreshSeconds、spatialCellSize、worldUnitsPerPixel | 防御参数移到单位属性；不保留全局 defenseConstant、minDamage 或元素字段 |
| TbPerformanceScenario | 保留 ID 1–3 与原有测试行为，新增独立 Combat 类型及测试 ID；关联 combatRulesId、角色、怪物、场地、测试策略 | 功能测试和压力测试分别明确出生数量、补充频率、持续有效单位数、事件负载 |
| __beans__ / __enums__ / __tables__ | 补属性值结构、属性类型、技能投递类型、Combat 测试类型及新表注册 | 生成 C# 和全部受影响 bytes 同步交付 |

属性 ID 建议 1–14，属性方案建议 1=玩家、2=近战怪；规则建议 ID 1。首个启用角色沿用 GameConfig.initialCharacterId，首个怪物可选现有 10001；玩家默认技能可从 20001 起进行视觉核验，怪物攻击关联另一条经核验的技能。未核验动画前不靠资源名称猜测攻击语义，也不擅自把同一个技能改成不同用途。

TbSkillCombat 是技能机制配置，TbSkill.visualSetId 是表现引用；两者分离，允许多个表现技能明确引用同一机制配置而不复制默认参数。TbAttributeProfile 也是表中明确配置，不是代码兜底。

| 判定项 | 对抗有效值 | 万分比阈值 | 必测边界 |
|---|---|---|---|
| 命中 | 命中 100，对方闪避 25；参数均为 1 | 8000 | 随机 8000 命中，8001 未命中 |
| 暴击 | 暴击 25，对方抗暴 100；参数均为 1 | 2000 | 随机 2000 暴击，2001 非暴击 |
| 参数权重 | 命中 100×2，对方闪避 100×1 | 6666 | 不四舍五入到 6667 |
| 必中 / 必不暴击 | 一方有效值大于零，另一方为零 | 10000 / 0 | 随机区间包含 1 和 10000 |
| 双方均为零 | 命中或暴击分母为零 | 按规则表 10000 / 0 | 不出现 NaN，不读取代码兜底 |

关闭浮动的指定测试输入 R=1、无闪避无暴击无防御、忽略飞行时，玩家每击 20，击杀 40 生命怪需要 2 次命中；首击 t=0，第二击 t=0.5 秒。正式浮动开启后伤害为 16–24，两次命中未必击杀，需要 2–3 次。怪物伤害取整为 6–9，100 生命玩家需 12–17 次有效命中；该区间不计暴击、闪避、移动与无敌拒绝，不能当作实际生存时间。

统计估算采用 E[伤害] = 命中概率 × ((1−暴击概率)×E[Int(基础值×R)] + 暴击概率×E[Int(Int(基础值×R)×1.5)])，期望应按离散随机分布求和。不能在取整前直接用平均随机倍率和平均暴击倍率相乘来代替精确结果。

调优顺序：先锁定命中次数与攻击间隔，再调追击速度和玩家受击节奏，然后调同屏密度，最后扩展防御与成长。记录命中次数、实际击杀时间、每秒有效伤害、无敌拒绝量及存活时间，避免只看面板战力。

## 8 运行时架构与生命周期

初始化由 IConfigService 读取生成配置并验证，通过后转为只读原生配置快照供 Burst 使用。Job 中不访问托管字典、Luban 对象或 YooAsset。快照只在入局时建立，退出时随战斗生命周期释放，不形成第二份人工维护配置。

建议在 Features 内建立 Combat 模块，复用 Core 合约，禁止直接依赖 Performance 功能。性能入口只请求同一 Combat 模块运行测试场景，不另写一套简化战斗逻辑。需要两入口共用的启动选项由 App 统一解析，避免正常游戏和性能场景同时生成实体。

固定顺序：输入 → 出生 → 属性脏数据重算 → 移动 → 空间索引 → 寻敌及攻击 → 弹丸扫掠 → 伤害结算 → 死亡回收 → 表现同步。寻敌使用均匀网格，按范围覆盖相关格；先精确过滤再选择最近目标。怪物追玩家为线性遍历，禁止每只怪扫描全部怪物。

单位属性采用固定布局组件存热数据，修改列表只在变化时重算。伤害请求使用原生队列与稳定排序，主线程只消费必要的玩家生命变化及汇总结果。池化实体必须清理目标、冷却、无敌、生命和事件状态；地图退出时释放池、原生容器与资源句柄。

正式表现需播放已确认的站立与移动帧，沿用 TbVisualSet → TbAnimationClip → TbResource 链路。提取可共享的 ANI 解析与渲染支持，不复制 PerformanceFeature 私有实现。未确认的攻击/死亡动作不猜测，可使用明确的简单反馈；不能将首帧贴图移动计为动画验收通过。

## 13 独立 ECS 会话实施记录

继第 12 节后，新增 `Roguelike.Features.Combat.Ecs`，由 `CombatSession` 管理局内实体、固定时钟、原生配置快照、空间网格、伤害请求与弹丸池。`CombatTickSystem` 显式驱动 Burst `CombatTickJob`，不自动加入逐帧系统组，避免绕过规则表补算上限；每 tick 完成后才允许读取结果或释放资源。

- 顺序：移动与建网格 → 生成全部攻击 → 弹丸相对运动扫掠 → 按目标生命周期/攻击者生命周期/攻击序号排序 → 调用统一伤害模块 → 死亡失活/补怪 → 变换同步。

- 最近目标按空间格过滤、精确距离选择，等距按生成序号；无目标不消费冷却。近战在圆边缘停步，边界比较仅容忍平方距离的一个 float ULP，解决舍入导致停步却不能攻击的问题，不新增策划范围值。
- 弹丸组件记录出生快照，旧弹丸对运动目标做相对扫掠，新生弹丸从攻击阶段的位置开始；第一次几何接触即失活，闪避不穿透。池容量由唯一弹丸发射者寿命与表内最短间隔推导，容量异常明确失败而不静默丢攻击。

- 帧补算达到上限后保留积压并记录峰值；暂停或玩家死亡不推进模拟。会话退出只销毁自己的实体并释放原生容器，不影响调用者世界或其他实体。

- 圆心每批取角色当前位置；已出生怪物沿既有移动/前摇/F4 攻击流程追踪，不随圆心瞬移。角色保留原场地限制，怪物允许在场地外出生和追入，不将圆周坐标夹到矩形边界。
- 无玩法存活上限；优先复用死亡槽，不足时在 Job 同步完成后增加实体和原生容器容量。每次出生更新生命周期，旧攻击/弹丸目标代际不能污染复用槽。
- 表现绑定随会话增加槽位，复用已加载纹理、材质及网格；重开隐藏全部怪物，退出释放已增长实体及容器。
- 技术边界：整圆 2π、整数抽样精度、容器容量及整数溢出保护属于算法/存储机制，不是玩法数量限制。
- 验收：首批时点、连续批次数、半径及跟随圆心、靠边不夹回、追踪、突破旧容量、槽复用、暂停/死亡冻结、重开随机复现、新槽渲染及生命周期清理；先 Unity，用户确认后才允许 Win64。

## 波次与半径修正（最新规则）

- 用户修正半径为 1000 逻辑像素（当前换算 10 世界单位）。
- 一波 15 只，波内逐只间隔 200 毫秒（0.2 秒），不是瞬时生成十五只。原 1 秒作为波间等待，首波同样等待。
- 首波首只 1.0 秒、末只 3.8 秒；第二波首只 4.8 秒。固定 tick 向上量化间隔，消除 float 的 0.2 秒表示误差造成的额外一帧。
- 每只生成时取角色当前位置作圆心。暂停、死亡、重开、动态扩容及槽位复用规则不变。
- runtime 诊断红圈直接读取场景配置；仅本次 Editor Play 存活，不保存 Scene/Prefab，退出回收诊断材质与绘制对象。
