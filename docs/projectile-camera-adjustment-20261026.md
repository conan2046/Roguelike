# 弹道可见性与镜头调整

## 已确认范围

依据本轮试玩反馈，让正常开局即可看到子弹的飞行与命中，同时将可见地图的宽、高扩大为原来的两倍。不加入留阵眼、围合判定或新攻击操作。

## 方案与源表

- `TbMap`：地图 1、101 的 `cameraViewportHeightPixels` 从 750 改为 1500。现有正交相机按此字段计算，模型、碰撞、攻击距离和地图本身的尺寸保持原值。同宽高比下可见面积为原来的四倍。
- `TbRunBuild`：101 保留本命护体罡环，开局增加追星飞刃；102 保留本命寒霜灵阵，开局增加扇形焚天炎符，并将炎符纳入可升级目录。各占一个正常武器槽，沿用现有伤害、冷却、星级与槽位规则。
- `TbStage`：两个切片入口的 `initialSkillIds` 与上述初始武器保持一致。旧关卡的技能和武器池不变。
- `TbAnimationClip`：已有 Projectile 飞行片段改为循环播放，使飞行中的弹体持续运动；命中片段保持原有非循环播放。继续使用正式 ANI/PNG，无新增表现资产。
- 本轮增加切片开局火力，属于解决弹道体验的配置调整，不宣称完成整体数值平衡。

## 调用链与边界

源 Excel → Luban 生成 C# / bytes → 统一配置服务 → `CombatRunDefinition` / `CombatBuildState` → `CombatSession` 的原生弹丸投递 → `CombatEntityVisuals` 飞行与命中播放。

镜头由 `CombatRuntimeRunner.UpdateCameraFit` 消费 `TbMap.cameraViewportHeightPixels`，跟随和地图边界仍由既有代码处理。

采用当前项目的加载期共享资源、Entities 弹丸池、命中表现池和统一退出清理。资源仍归 `CombatVisualResources` 所有，调用方取消令牌和资源释放顺序不变；不增加异步任务、UI 节点、单例或业务硬编码。沿用正式 HUD 的槽位和武器名称显示。异常与清场继续走既有 Runner / 会话关闭流程。

Tower 参考工程的 `GameScript/HotFix/Battle/Skill`、`Entity` 在本机不可访问，已按本次范围检查，不扩展扫描。基于本项目现有实现调整配置，不引入旧表生成链或参考工程运行时架构。

## 验收

1. 源表与 Luban 生成物一致，配置强引用和初始技能一致性通过。
2. 两个职业均从真实选角入口进入；保留本命武器，开局拥有对应弹道武器，可观察飞行和真实命中。
3. 同分辨率下正交半高从 3.75 变为 7.5；两个职业使用相同新视野；地图边缘跟随不露出地图外。
4. 覆盖现有炼器换技能、投递及退出生命周期回归，确保新增开局武器没有破坏本命炼器。
5. Unity 编译及相关回归通过后，留在真实试玩入口供用户人工验收。无 Win64 构建、提交或推送。
