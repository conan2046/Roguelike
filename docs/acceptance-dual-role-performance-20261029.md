# 双职业自然流程与 2000 档性能复核（2026-10-29）

## 结论

修复性能采样窗口及阶段 Recorder，并修复自然流程发现的试炼按钮被 HUD 遮挡问题。两种 2000 档完整采样均未达到原性能门槛；四份双职业自然输入样本均以失败结算，尚未验证当前版本的自然通关、炼器领取与跨局解锁闭环。测试执行通过只证明观察、交互、保存和清理完成，不代表玩法目标或性能预算通过。

本轮未调整正式数值、表、生成物、技能绑定或性能门槛，未构建 Player。提交与推送不改变上述验收结论；用户人工手感验收仍待进行。

## 修复与范围

### 性能采样

- `CombatPerformanceProbeTests` 的六个表现阶段 Recorder 增加 `WrapAroundWhenCapacityReached`，容量仍为 1，保留每帧求和语义。
- 完成预热尾段后建立实际采样基线；退出条件以已经送入 `Advance` 的墙钟终点为准，避免最后一个渲染帧结束而模拟输入未送达。
- 报告新增要求采样时长、实际送入模拟时长；断言完整窗口及逐帧 Tick 与会话统计一致。不补造 Tick，不隐藏积压。
- 新增 Explicit 的 2000 档完整入口，复用原基础／六超武压力夹具、Luban 场景 5 门槛及恢复清理链；原三档入口保留。

### 试炼 UI

首轮真实射线点击 `ActivateAltar` 命中了 `BuildSlots`：战斗 HUD 已采用 Overlay，试炼 HUD 仍为 Camera 模式，二者的排序值不能维持原本层级意图。

- 通过本项目 MCP 将正式 `TribulationHud.prefab` 的 Canvas 改为 Overlay、开启像素对齐；完整 diff 仅两个属性，原布局和排序 101 均保留。
- 同步 `CombatTribulationPrefabBuilder`，避免以后生成缺失 UI 时重现旧模式。
- 沿用已有 HUD 的显示模式与 Prefab 所有权；没有新增运行时配置副本、布局覆盖、预览资产或 Scene 修改。
- 本轮定向检查的 Tower UIKit 参考路径不存在，故依据当前项目 Canvas、射线与加载释放链完成修复。未迁入 Tower 业务或新资源管理机制。

## 失败与恢复记录

- 首轮批量输入夹具遇到真实 UI 遮挡；同批另一角色出现 Entities Graphics 绘制越界。UI 已修复，夹具改为每渲染帧一次模拟／表现更新。后续四份完整样本均未复现绘制异常，但这不足以证明该异常所有触发条件均已消除。
- 第二组首次执行被延迟脚本导入／域重载中断（job `372ede5e706343f79fa3f9a8cd7725c1`）。经 MCP 停止、清除失效任务、完整导入并核实空闲后重跑；未完成目录 `20261029-135928-0` 不计入样本。
- 第一次追加 EditMode 分组回归未能初始化，不记作运行通过。随后精确选择六项机制用例，6/6 通过（job `2e83e34765594ff78c451fc8fd803413`）：环境范围／阵营／唯一死亡、Boss 破阵、预警计数与炼器保星、失败试炼拒绝领奖、非敌方来源不能刷奖励、清阵取消待结算引爆。
- 最后追加 PlayMode UI 与生命周期回归，4/4 通过（job `aba84491ca754bcb9bec67bc96171c38`）：构筑选卡与隔离解锁保存、HUD 连续移动像素覆盖、角色加载取消排空、加载失败后重试及资源清理。受控解锁用例仍不替代自然目标可达性。
- 清场时保留了预期的注入加载失败日志，并发现 Unity Test Framework `PlaymodeLauncher.BackgroundWatcher` 在退出时的空引用；不是上述用例断言失败。通过正常域重载、清理隔离标记和本轮两个临时测试场景后，重新进入正式选角，Console 错误为 0。
