## 1. 产品定位

### 1.1 品类
Survivor-like（弹幕生存 / 肉鸽）· 单机 · **Steam 首发** · 后续移动端（ECS 必须）。

### 1.2 核心循环
- **局内**：移动躲避 → 自动攻击 → 拾取 → 升级选卡 → Boss → 结算。
- **局外**：选角色 → 进局 → 养成解锁 → 下一局。

### 1.3 核心产品卖点（**已确认 · M0 解锁**）
> 一局 15~20 分钟独特乐趣 = 低操作门槛的自动割草数量爽感 + 超武质变峰值 + 可见养成的长线目标；**差异化靠内容广度（81 只怪物共 7 系，远超竞品）与 Build/收集深度，不靠操作门槛**。
- **支柱1（战斗机制 · 低操作门槛自动割草）**：攻击自动化 + 极低操作门槛，玩家仍需 WASD 移动 / 走位 / 吃经验 / 避技能 / 找事件；靠单局同屏数量感与超武进化质变提供峰值爽点（VS 式极简，开发成本最低、受众最广）；81 只怪物（共 7 系）作为**视觉/内容广度**支撑割草 spectacle，非强制克制门槛（系克制列为 P2 可选深度，不进核心壁垒）。
- **支柱2（构筑机制 · 超武进化链 + 流派权重）**：选火系后火系出现率微偏向 → 自然成流派；武器 5 星 + 对应被动 ≥1 星 → 超武质变瞬爽（弹壳式）。卡池污染规则 = **混合**（基础纯随机 + 角色/武器专属微偏向，兼顾随机与 Build 成型，详见 §2.4）。
- **支柱3（成长/收集 · 可见养成 + 章节图鉴）**：8 向 + 武器/护甲/翅膀/坐骑/神器层叠模型，装备实时可见角色成长；6 系角色 × 81 怪图鉴 + Steam 成就驱动 20~50h 长线。
> M0 已解锁：USP 落定，可进入 M1（URP 切换 + 战斗最小闭环 + Luban 配置骨架）。

### 1.4 单局目标
15~20 分钟/局（优于 40min，更适合反复刷）；单张连续地图自由移动。

## 2. 局内系统（先定规则，再堆内容）

### 2.1 玩家 Player
移动（WASD/摇杆）+ 自动攻击（**低操作门槛自动战斗已定：攻击自动化，玩家仍需移动/走位，手动瞄准不纳入核心，列为 P2 可选**）。

### 2.2 武器 Weapons
- **武器槽：6 槽（已锁定）** — Brotato 式固定 6 槽，学习成本与开发成本最低。
- **局内成长 = 武器星级（已锁定）**：1★ → 2★ → 3★ → 4★ → 5★ → 超武；**局内只升星，不出现品质/等级概念**。
- **局外 = 品质（白→绿→蓝→紫→金→红）**：控制基础属性 / 初始效果 / 局外被动 / 成长上限（见 §3.2）；**品质不进入局内随机升级体系**。
- **超武条件**：武器 5★ + 对应被动 ≥1★ → 超武（弹壳式）；超武继承**星级**形态，不继承局外品质。
> **关键拆分**：**品质 = 局外成长；星级 = 单局 Build；超武 = 单局最终形态**。两者不复用，避免「Lv5 与 5★ 关系」「金 Lv3 与蓝 Lv5 谁强」「升级提什么」等语义冲突。

### 2.3 技能 / 被动 Skills & Passives
- **被动槽：6 槽独立（已锁定）** — 与武器槽独立，提升 Build 自由度。

### 2.4 Build 系统（规则层）
| 规则 | 定义 |
|---|---|
| 武器槽数 | **6（已锁定）** |
| 被动槽 | **6 独立（已锁定）** |
| 局内武器成长 | **武器星级 1★~5★→超武（已锁定，无 Lv 概念）** |
| 局外品质 | **白→红（已锁定），控制局外成长，不进局内随机升级** |
| 刷新 Reroll | 是否允许、次数/局（未定） |
| 锁定 Lock | 是否可锁卡（未定） |
| 放弃 Skip | 是否可跳过升级（未定） |
| 卡池污染 | **混合（已定）**：基础纯随机 + 角色/武器专属微偏向（选火系后火系权重轻度↑） |
| 进化 | 武器5★+对应被动≥1★→超武（已定） |
| 超级组合 | 几合一、是否占槽（未定） |
| 角色专属 | 是否改变卡池（未定） |
| Build 方向 | 火系权重微偏向（混合，已定方向） |

> **已定（混合）**：基础纯随机保证肉鸽随机性，角色/武器专属微偏向让玩家能轻度引导流派，不破坏随机骨架。火系权重提升幅度待 M3 数值（建议 +10~20%）。

#### 升级卡池类型（M2 前必须定义）
- **新武器**：获得未持有武器（武器槽未满时出现）。
- **武器强化**：已获得武器升 1★。
- **新被动**：获得未持有被动（被动槽未满时出现）。
- **被动强化**：已持有被动升级。
> **关键规则**：武器槽满后不再出现新的普通武器；被动槽满后不再出现新的普通被动。否则 CardPoolSystem 易反复改。

### 2.5 敌人 Enemies
近战 / 远程 / 范围 / 治疗 / 控制 / Boss；Spawn Director 见 2.7。**规模 = 81 只怪物（共 7 系）**，非 81×7。

### 2.6 Boss
阶段战 / 最终 Boss（18min 节点）。

### 2.7 Spawn Director（固定时间曲线 + 有限动态）
- 基础难度由**时间**决定：0~3min 低压 / 3~8 中压 / 8~13 高压 / 13~18 极限 / 18 Boss。
- 动态只调：Spawn 密度 ±10~15%、精英频率、敌人组合、掉落补偿。**不随玩家战力无限抬怪 HP**——保留 Build 成型后碾压的爽感。

### 2.8 地图 Map（参与游戏，非背景）
连续战场中根据**时间段、空间位置、随机规则**投放不同节奏事件，包括：精英事件 / 宝箱 / 特殊事件 / 商店 / 小Boss / 高压波次 / 最终Boss。**不强制固定顺序**，保证每局随机性。

### 2.9 掉落 Drops
经验球 + 金币/材料/血包/宝箱。

### 2.10 商店 / 事件 Shop & Events
节奏点：商店（购买/升级）、宝箱、特殊事件。

### 2.11 局内 UI
HUD / 升级选卡 / Boss 血条 / 小地图 / 伤害数字 / Buff / 技能状态 / Pause / 结算。

### 2.12 结算 Settlement
经验/掉落结算 → 局外转化。

## 3. 局外系统（结构参考弹壳，Steam 单机重构）

> 原则：从"时间门槛驱动（手游留存）"转为"内容目标驱动（Steam 长期目标）"。**第一版只保留：角色解锁 / 武器解锁 / 永久天赋 / 章节 / 图鉴。**

- **P1**：升星（碎片）→ 专属被动。

### 3.2 武器 Weapons（局外）

### 3.4 章节 Chapters

### 3.5 图鉴 Collection

### 3.6 装备 Gear（P1 再加）
6 槽；第一版不进。

### 3.7 宠物 / 高阶武器 / 挑战玩法（P2 再加）
**已删除**：巡逻挂机（16h AFK）、24h/4d 免费箱、每日任务 / 每日奖励 / 限时活动（FOMO）——不符 Steam 单机买断节奏。

## 4. 游戏流程 Game Flow
启动 → 主菜单 → 选角色 → 选关 → 战斗 → 暂停 → 死亡/胜利 → 结算 → 奖励 → 返回。

- **Steam**：Achievement / Cloud / Controller / Steam Deck 验证 / 语言 / 设置。

- **存档 Save System（§5.6）**：见下。

### 5.6 存档 Save System
- **Profile Save**：角色 / 武器 / 天赋 / 章节 / 图鉴 / 设置（Steam Cloud 同步）。
- **Run Save**：当前局临时快照，用于 Steam Deck 休眠 / 程序异常退出 / 移动端切后台；**死亡 / 结算后删除 Run Save**。
> 跨 Steam Deck / Mobile 安全落盘，避免进度丢失与跨端残留。

## 6. 技术架构
| 层 | 方案 |
|---|---|
| 数据层 | 数据表唯一源头 → Luban 生成 C# 与运行时数据 → 统一配置入口（武器/敌人/波次/升级/角色） |

- 渲染桥 `CocosAniInstancedPlayer`：kapai `.ani` → ECS 实例 AnimState，取代 UGUI RawImage（**关键桥梁，前移 M1.5 验证**）。

## 附录：Cocos ECS 框架模块清单与 rouge 映射

### A. 引擎核心模块
| 模块 | 说明 | rouge (DOTS) 对应 |
|---|---|---|
| 实体管理 | 创建/生命周期/批量操作 | `EntityManager`（原生） |
| 组件 Component | 纯数据 + 组合模式/数据建模 | `IComponentData`（原生） |
| 系统 System | 4 种系统类型 + 定时器 + 流式查询(链式) | `SystemBase`/`ISystem` + `EntityQuery`（原生） |
| Archetype | 内存布局/批处理/缓存友好 | DOTS Chunk/Archetype（原生） |
| 组件索引 | 按组件快查实体 | `EntityQuery`（原生） |
| 脏标记 | 变更检测优化 | `ChangeFilter`（原生自动） |
| 事件系统 | 类型安全 + 装饰器 + 编译时检查 | **缺口①**：自研轻量事件组件 + ECB |
| 场景管理 | 切换/持久化/状态 | SubScene + 已有存档(§5.6) |

### B. 工具/产出模块
| 模块 | rouge 是否需要 |
