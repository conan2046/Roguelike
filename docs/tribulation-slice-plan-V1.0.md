# 借劫炼器体验切片 V1.0

2026-10-26。用户已批准按讨论方向直接制作可玩切片，并授权当前工程Unity操作自主通过MCP执行；跨项目操作冲突必须停止确认。本文把该授权落实为数据、实现与验收范围，不新增提交、推送、Win64构建或其他系统开发。

## 体验目标

在一张地图中选择磐岳或周天。保持自动攻击和移动操作，玩家主动前往雷坛引劫，把锁定落点的雷击引向怪潮；完成试炼后为本命法器选择一种行为变化。两种职业需要不同走位，最终Boss同时检验近身承压、持续阵地和引雷决策。

切片包含两个职业、每职业三个可转向炼器分支、三座雷坛、一个多阶段Boss、角色选择和胜负重开。原stage1的18分钟时间线和现有手调Scene/Prefab保留。切片使用独立关卡101/102、同一地图101，Boss在240秒进入；该时长是本次体验参数，不是首发内容规模或已验证平衡结论。

## 既有架构与参考

现链路为启动组合根 → CombatRunDefinition → CombatRunModel/CombatBuildState → CombatRunCoordinator → CombatSession固定步进/ECS → Rendering与正式UI。Luban生成配置为唯一规则入口。已有实际投递支持扇射、环射、穿透、连锁、固定/随身持续区域与换目标落雷，优先复用。

Tower指定Battle路径本轮仍不可访问，无法核对其具体Manager/Entity/Skill/Buff、UI绑定或异步释放实现。采用当前项目已验证的纯逻辑模型、权威伤害结算、稳定生命周期及资源句柄所有权；调整其可扩展入口以承载切片；拒绝网络、热更、全局单例、旧表链和业务硬编码。

## 规则与数据流

| 模块 | 规则 | 权威所有者 |
|---|---|---|
| 角色选择 | 读取入口表列出的两个切片关卡；点击后加载对应角色与本命法器；可从局内或结算回到选角 | 独立切片入口控制器；不接管其他关卡 |
| 磐岳 | 有效受击蓄能，达到表内次数后进入铁壁，暂时减伤并触发近身反击；结束后可再次积累 | 固定步进伤害状态；UI只显示 |
| 周天 | 移动达到表内距离后留下持续阵域；阵域按时脉冲，达到重叠条件时引爆并消耗参与阵域 | 切片协调器及会话正式范围伤害 |
| 雷坛 | 按表内时点解锁；靠近后显示引劫按钮，玩家自行选择启动时机 | 单局切片状态，保存坛ID与代次 |
| 引劫 | 脚下生成落点预警，锁点后延迟命中；雷击能伤玩家及怪物，Boss使用独立表内倍率 | 会话几何与CombatDamage正式结算 |
| 试炼 | 在表内时限存活并达到引雷命中怪物目标；成功进入炼器选择，失败消耗本坛机会并说明原因 | 纯状态模型；真实命中事件累计 |
| 炼器 | 每个职业针对本命法器提供三个真实投递形态；领取后同槽替换，升星不覆盖该分支；后续试炼允许转向其他分支 | CombatBuildState；旧面板代次失效 |
| Boss | 保留正式Boss死亡胜利链；按生命阶段改变雷区数量/频率，高阶段可清除危险区域内的玩家阵域 | 切片规则及正常死亡/结算 |
| 暂停/升级/结算 | 所有试炼、预警、阵域与Boss计时随正式模拟冻结；结算终止待领奖与延迟雷击，重开清空旧代次 | Coordinator及固定步进时钟 |

伤害不通过测试注入或直接绕过规则改血：新增会话范围命中入口复用CombatDamage、免伤/闪避/无敌、生命扣除、死亡事件和统计；怪物死亡仍产生原经验/宝箱事件。环境攻击源属性、对玩家/普通怪/Boss的倍率、技能引用及几何均来自表。新增玩家减伤为零时数学恒等，不改变旧关卡公式。

## 数据表与初始标定

| 表 | 内容 |
|---|---|
| TbTribulationSlice | stage强引用、职业显示名/说明、本命武器、职业规则、试炼规则、炼器候选、UI入口引用 |
| TbTribulationRule | 雷坛位置与解锁时点、接近距离、试炼时限/命中要求、预警和落雷间隔/范围、环境属性方案/倍率、Boss阶段列表、表现引用 |
| TbTribulationSignature | 磐岳受击蓄能/铁壁/反击；周天留阵距离、寿命、脉冲、重叠引爆、容量等明确字段 |
| TbTribulationRefinement | 本命武器与结果技能强引用、行为说明、伤害/间隔/范围修正及其代价 |
| TbTribulationUi | 入口关卡列表、正式UI Prefab资源、所有显示文本/格式与预警颜色等表现配置 |
| 既有表扩展 | 独立Stage/StageRule/Map/SpawnPhase/BossEncounter/属性/构筑行；周天角色补正式属性与初始技能；Stage增加可选slice引用，旧行留空 |

使用项目既有四行Luban表头与强引用语法。源工作簿、定义注册、生成C#与bytes同步交付。新增参数是供试玩调优的初值，正式数值以Excel为准，文档不再维护第二套可变默认值。

数值采用现有CombatMath/CombatDamage的实际取整、攻防和对抗规则；参考数值技能EHP/EDPS及战斗节奏理论，仅用于比较风险和收益，不替换现有公式。检查两职业在近身承压/持续走位上的实际差异，三分支要出现覆盖、命中组织或站位变化并有明确代价；不以名称/光效或单次伤害倍率冒充质变。普通怪、环境攻击、Boss属性从现有表基线派生，后续通过真实单局记录校正。

## 实现分工与生命周期

- Run：切片定义验证、雷坛/试炼/奖励代次、职业可观察状态、炼器分支持有；不访问Unity对象。
- Ecs：固定步进受击蓄能、减伤、范围命中、死亡与统计。权威状态修改必须沿同一会话入口完成。
- Runtime：接近检测、输入请求、正式事件消费、选角/切片运行器创建与退出；同一入口只允许一个战斗World。
- Rendering：读取权威预警/阵域与落雷事件；复用正式ANI/材质，临时几何只驻留内存，退出销毁。
- UI：新增正式Prefab，不覆盖既有手调Prefab。布局、字体、绑定序列化；运行时只刷新数据/可见性并响应点击。
- 启动入口：新增技术启动标志与Editor菜单；业务关卡ID和角色列表从Luban入口表读取，不在菜单或MonoBehaviour复制。
- 异步加载：入口拥有组合取消令牌，切换/退出取消未完成加载；资源句柄先于资源服务释放。旧角色选择、炼器面板和旧代次回调全部拒绝。
- 纯技术边界：圆形预警的离散顶点数、排序层技术深度、数学恒等值、命令行开关与UI绑定对象名属于实现参数；颜色、尺寸、时间、伤害、文本、资源键、数量和业务ID仍全部读表。

| 编号 | 必须证明的行为 |
|---|---|

| AC02 | 正式入口可选两个职业；入局角色/本命武器/规则正确，退出选角无多余World或资源 |
| AC03 | 磐岳实际受击后蓄能、减伤、反击、到期恢复，暂停不推进；没有无条件无敌 |
| AC04 | 周天实际移动留阵、持续脉冲和重叠引爆，改变路线能改变伤害覆盖；阵域有容量和清场 |
| AC05 | 靠近雷坛后真实按钮引劫；锁点预警、延迟雷击、对玩家/怪物实际伤害及试炼命中进度均可见 |
| AC06 | 试炼成功/失败、升级与领奖冲突、死亡终止均有明确结果；只发一次奖，旧回调无效 |
| AC07 | 两职业各三分支均发生实际投递/命中行为变化；同槽替换、升星保留、后续转向和重开清零 |
| AC08 | Boss各阶段实际触发对应落雷/破阵压力，死亡走原胜利链；真实失败、结算重开均可到达 |
| AC09 | Unity编译及相关Edit/Play测试通过；通过正式入口、真实UI射线和输入帧验证完整游玩，不以测试注入代替自然达成 |
| AC10 | 退出/取消/部分加载失败无World、回调或临时网格遗留；无独立预览资产和未授权场景/Prefab覆盖 |
| AC11 | 最终在Editor打开切片供用户体验，报告已验证/未验证项；不冒称旧M1.5的2000档性能问题已解决 |

自动化先于用户人工体验；用户人工反馈保留为最后验收项。测试工具可以缩短边界场景，至少一条实际雷坛→渡劫→炼器→Boss/结算链必须以正常游戏规则到达并留新证据。

## 首轮实际体验调整记录

正式入口实际走通了磐岳受击铁壁、雷坛点击、环境落雷杀敌、升级冻结、渡劫领奖、自然死亡和结算重开。周天通过实际移动触发留阵与折返引爆，并走到第二坛的正常炼器面板。UI射线证据和输入帧记录保存在本轮`.local/tribulation-slice-20261026/`，不把测试伤害注入当作游玩证据。

磐岳后两坛实测引雷命中为零，周天首坛不足、第二坛达标。原雷区小于部分炼器清怪范围，先将TbTribulationRule.strikeRadiusPixels调整为更大的试用范围，继续保留锁点、预警和双方受伤规则；不通过无条件发奖替代真实命中。调整值只保存在源表，仍须重新生成并复测。

百分比回复的向下取整属于正式整数生命结算语义；为两个职业补充受伤后领奖、升级/炼器排队与旧回调回归。此记录不宣告Boss、六个分支或全部验收门禁已完成。

后续输入帧实测中，磐岳多个构筑在后段普通怪压力下于192–206秒自然失败，尚未到240秒Boss。先仅重标定切片专属属性方案101/102的初始生命和攻击，保留原关卡、怪物、Boss和时间线，随后重新验证自然通关。该调整属于试玩初值，不宣称完成平衡。
