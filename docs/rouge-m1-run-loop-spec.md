## 2. 设计目的

1. 用当前真实工程完成第一条可玩的 Survivor-like 单局循环，而非继续扩大性能测试场景。
2. 验证移动、自动攻击、击杀、经验吸附、连续升级、Boss 和结算之间的节奏是否成立。
3. 将正式玩法从 `TbPerformanceScenario` 中拆出，避免测试参数继续承担业务配置。
4. 建立后续增加怪物、武器、升级项、关卡和 UI 时可复用的数据驱动边界。
5. 保留千怪压力验证能力，但不让压力测试拖慢每次日常回归。

## 5. 玩家流程

```text
Loading
  └─ 配置和资源成功 → Playing
Playing
  ├─ 经验达到阈值 → UpgradeChoice ─ 选择完成 → Playing
  ├─ 玩家生命归零 → DefeatSettlement
  └─ 到达 18:00 → Boss
Boss
  ├─ 玩家生命归零 → DefeatSettlement
  └─ Boss 死亡 → VictorySettlement
VictorySettlement / DefeatSettlement
  └─ 点击重开 → 清空本局状态 → Playing
```

状态规则：

1. `Loading` 只负责读取 `TbStage` 及其引用、异步加载共享资源并创建单局。
2. `Playing` 推进模拟时钟、单位行为、普通刷怪、攻击、掉落和拾取。
3. `UpgradeChoice` 冻结战斗模拟，UI 继续响应；选择成功后才恢复。
4. 到达 Boss 时间的同一固定 tick，先尝试落地阶段完整周期的末只普通怪；仍因占位未执行的普通请求全部取消，Boss 只生成一次。
5. 结算状态冻结模拟并显示本局统计；同一局只能产生一次结算结果。
6. 重开复用已加载的共享资源，清空实体、掉落、升级、Boss、计时器、随机流和 UI 状态。

## 6. 启动与架构

| 入口 | 参数 | 数据来源 | 用途 |
|---|---|---|---|
| 正式单局 | `-stage <stageId>` | `TbStage` 及正式业务表 | 玩家体验和 PlayMode 验收 |
| 战斗测试 | `-combatScenario <scenarioId>` | `TbPerformanceScenario` | 指定战斗测试场景 |
| 性能测试 | `-performanceScenario <scenarioId>` | `TbPerformanceScenario` | 千怪、帧率和报告 |

三个入口互斥；重复参数、缺少 ID、非正整数或多个入口同时出现时应在启动阶段失败并给出明确错误。正式单局不得读取 `TbPerformanceScenario`。

运行时分层：

| 层 | 职责 |
|---|---|
| Configuration | 从统一配置服务读取 Luban 表，校验引用完整性 |
| Core | 保存无 Unity 依赖的单局状态、确定性随机、候选筛选和结算规则 |
| Features/Combat | 驱动 ECS 单位、攻击、掉落、刷怪、升级和 Boss |
| Infrastructure | 通过 YooAsset 加载正式 Prefab、ANI、纹理和字体资源 |
| Presentation | 绑定 ECS/核心只读状态，刷新 HUD、选卡、Boss 血条和结算面板 |

新增 `CombatRunDefinition` 作为单局入口的只读聚合结果。它只能由配置构造器从 `TbStage` 及引用表生成；缺表、悬空引用、阶段重叠、时间不连续、权重非法或资源类型错误时直接阻止开局。

| 单位 | 定位 | 生命 | 攻击 | 防御 | 移速 | 身体半径 | 默认技能 |
|---|---|---:|---:|---:|---:|---:|---:|
| `10010_btm108` | 标准地面怪 | 40 | 8 | 0 | 2.0 | 0.200 | `20002` |
| `10011_btm109` | 轻型飞行怪 | 30 | 7 | 0 | 2.6 | 0.200 | `20002` |
| `10012_btm110` | 慢速高血怪 | 65 | 10 | 0 | 1.5 | 0.112 | `20002` |
| `10013_btm111` | 快速高攻怪 | 50 | 12 | 0 | 2.2 | 0.174 | `20002` |

规则边界：

1. 第一波遵循该阶段的波后等待，不在开局首帧突发生成。
2. 每个阶段必须恰好容纳整数个完整周期；末只可在阶段结束时刻生成，仍因出生占位未落地的旧请求在切换时取消，新阶段按自身等待规则开始。
3. 怪物在玩家周围圆周生成，半径从表读取；不在代码中添加固定坐标。
4. 本轮不设置“最大存活怪物数”作为玩法限制。实体池容量属于技术容量，必须按表配置推导并在开局校验，不得静默丢怪。
5. 未来动态密度调整只允许在表定义的基准生成率附近变化，目标区间为 ±10%–15%；不按玩家战力无限提高怪物生命。

## 9. 战斗与技能表现

角色 `10001` 正式开局默认技能仍为 `20001`。`20014`、`20032`、`20028`、`20043` 进入升级候选和专项测试，覆盖 Projectile 与 TargetArea 两种投递类型。具体攻击间隔、射程、速度、寿命、伤害和碰撞均来自 Luban 表。

弹丸生命周期：

```text
Inactive → Launch → Flying → Impact → Inactive
                         └─ 超时/越界 → Inactive
```

1. `Launch` 在攻击冷却完成时产生弹丸；本轮没有已确认的独立释放片段。
2. `Flying` 绑定共享 ANI 网格，显示位置和方向来自 ECS 弹丸实体。
3. `Impact` 只在首次有效命中时进入；同一弹丸不得重复产生伤害请求。
4. 命中 ANI 播放结束后回收表现对象；没有命中 ANI 时可直接回收。
5. 超时或越界只回收，不伪造命中。
6. 动画资源按技能表显式引用并共享加载，禁止每颗弹丸重复加载资源。

目标位置群体技能生命周期：

```text
Ready → 锁定最近合法目标位置 → AreaActive → 单次范围结算 → 表现结束 → Ready
```

1. `20028` 和 `20043` 不创建移动弹丸，释放点锁定为攻击触发时目标的位置。
2. 群体伤害按配置半径筛选全部敌方单位，同一释放对同一单位只结算一次。
3. `20043` 的三段片段作为同一表现集合在目标位置叠加播放，不按后缀推断先后关系。
4. 目标在结算前死亡或被对象池复用时，使用生命周期编号拒绝陈旧伤害请求。

## 10. 经验、拾取与升级

普通怪死亡时生成一个经验掉落实体；Boss 是否掉落经验不影响胜利判定，M1 默认不结算其经验。

经验掉落状态：

```text
Dropped → 玩家进入 magnetRadius → Magnetized → 距离 ≤ pickupRadius → Collected
```

1. `Dropped` 保持死亡位置。
2. `Magnetized` 以表中速度向玩家移动，同一掉落只能绑定当前玩家一次。
3. `Collected` 在同一模拟 tick 内增加经验并失活，禁止重复拾取。
4. 玩家获得经验后循环检查升级阈值。若单次经验跨过多级，则逐级排队，每次完成一轮三选一后继续弹出下一轮。
5. 进入 `UpgradeChoice` 后，刷怪、移动、攻击、伤害、掉落和单局计时全部冻结。

经验首版提案：普通怪经验值为 1。逐级阈值使用下式生成源表：

```text
RequiredExp(level) = round(5 × 1.35^(level - 2)), level ≥ 2
```

运行时不计算该公式，只读取 `TbExperienceLevel.requiredExperience`。确认后应先生成 2 级到 M1 最大可达等级的逐级值，并通过表校验确保等级连续、阈值为正。

升级候选规则：

1. 使用本局独立的确定性随机流，固定种子下候选顺序和结果可复现。
2. 过滤未解锁、前置条件不满足、已达最大阶、目标不存在和当前状态不可用的候选。
3. 对剩余候选按正整数权重进行无放回抽取，返回 3 个不同选项。
4. 候选不足 3 个视为配置错误，不能用代码内置选项补位。
5. 选定后先校验当前面板代次，再应用属性修改，防止双击或陈旧按钮重复生效。
6. 强化效果按 `Add → AddPercent → Multiply` 的固定顺序结算；该顺序进入配置协议和测试。

M1 候选类型建议覆盖：当前武器强化、攻击间隔、最大生命、移动速度和立即恢复。各项具体数值在下一阶段使用数值技能生成平衡表并交用户确认。

## 11. Boss

1. 模拟时钟到达 18:00 时进入 `Boss` 状态，停止普通怪波次。
2. Boss 在配置半径上生成一次；暂停、连续升级、切换 UI 或帧率波动不得重复生成。
3. Boss 固定使用 `10032_btm311` 和独立 `TbAttributeProfile`，不修改普通怪属性方案。
4. M1 Boss 先使用单一攻击模式，不增加多阶段、召唤或场地机制。
5. 玩家先死亡则失败；Boss 先进入死亡结算则胜利。同 tick 同时发生时按伤害请求的确定性顺序结算，并以最终状态规则测试锁定。
6. Boss 死亡后立即冻结模拟并进入胜利结算，不等待经验或死亡演出结束才判定。

Boss 首版属性为 3,000 生命、12 攻击、5 防御、1.6 移速。现有角色 20 攻击时，基础 `20001` 对 5 防御的单次期望基准伤害约 16，0.5 秒间隔对应约 32 DPS；获得正常攻击成长后目标 TTK 为 45–75 秒。实机结果超出区间时只调整 Boss 属性表。

## 15. 数值验证方法

刷怪节奏用以下指标验收：

| 指标 | 计算 | 用途 |
|---|---|---|
| 生成率 | `unitsPerWave / wavePeriod` | 确认四阶段压力递增 |
| 清场差 | `玩家 KPS - 生成率` | 判断场上数量趋势 |

| 升级频率 | `阶段经验产出 / 当前等级阈值` | 避免长时间无选择或连续弹窗过密 |
| 生存余量 | `玩家 EHP / 敌方有效 DPS` | 校验 Boss 和极限阶段失败压力 |

运行时代码接入后至少用三组 Build 校验：无强化基线、正常随机 Build、偏弱随机 Build。M1 不用目标留存、LTV 或商业化指标反推战斗数值。
